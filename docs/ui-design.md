# Композиция интерфейса Niceproxy

## Документированные контракты Alpha UI

Источник — документация Alpha UI 0.4.12-niceproxy.3 (локальное расширение 0.4.11): `docs/consumer-agent-rules.md`,
`agent-guide.md`, `buttons.md`, `forms.md`, `motion.md`, `icons.md` в исходниках
выпуска. Для локальной разработки библиотека находится в `../alphas-base`.

- Компоненты: публичный API `@alpha/react`; шрифты и стили `@alpha/core`.
- Шрифты: основной текст Noto Sans, заголовки/навигация Manrope, технические
  значения Fira Code. Поэтому адреса и DNS-значения — `Text font="mono"`,
  а не строковые подписи DrawerButton, которые не имеют свойства шрифта.
- Поверхности и интервалы: Card и Stack; оболочка AppShell, режим container.
- Действия: Button default/simple/blank, IconButton для действия с иконкой.
- Поля: управляемые TextInput/Select/Switch. Inside — документированное
  расположение редактируемой подписи; явное значение приоритетнее состояния.
  Сохранён `showIcon=false` у обычных полей для стабильной геометрии при busy;
  у пароля иконка включена через публичное свойство.
- Навигация: DrawerButton для переходов к категориям/настройкам; технические
  данные отображаются отдельными Text. Badge используется только для уведомлений
  внутри навигации, в обычных состояниях сервиса не нужен.
- Движение контролов: один `installControlMotion`; обычные состояния библиотеки сохраняются.
  Полноэкранные View Transitions и принудительная прокрутка убраны по запросу
  пользователя. Переключение экрана — синхронный React commit без растворения страницы.

CSS приложения, inline-стили, переопределения токенов и внутренних классов
компонентов отсутствуют.

## Решения приложения

Это решения по логике Niceproxy, а не дополнительные правила Alpha UI:

- Список маршрутов показывает протокол, состояние и оба адреса. Одна главная
  кнопка создаёт маршрут; открытие записи — вторичное действие.
- Просмотр, создание, редактирование и подтверждение удаления — отдельные экраны.
  Тип подключения выбирается до начала ввода. Один заголовок страницы заменяет
  повторяющиеся заголовки оболочки и формы.
- Сервис показывает сохранённую и применённую ревизии. Успех — только при healthy
  и совпадении ревизий. Назначение портов не занимает место перед списком маршрутов.
- Cloudflare DNS доступен через настройки; старый hash `#cloudflare` сохраняется.
  Записи отображаются с отдельным действием редактирования.
- Иерархия 1–2–3 из задания пользователя реализована штатными вариантами
  default/simple/blank. Не более одного главного действия в текущем состоянии.

## Стабильность данных

Обновление config/health/port-owners не перезапускает авторизацию и не заменяет
экран общей загрузкой. Мутации сериализованы. Чтения предыдущей сессии и чтения,
начатые до успешной мутации, не заменяют актуальные данные. Старый ответ DNS
не перетирает сохранённую запись. Проверяются Back/Forward и reduced motion.

## Компоновка страницы

`AppShell viewport="full" serviceMode="static" showAccount` заполняет
viewport и включает canvas документа. Профиль сохранён, имеет доступное название
«Аккаунт администратора» и открывает доступ к панели.
`Page width="form"` ограничивает ширину формы токеном 44rem с внешними
адаптивными интервалами. Заголовок располагается на canvas, отдельная
карточка вокруг заголовка не создаётся. У страницы входа `Page viewport="full"`.

API реализован в библиотеке и поставлен локальными архивами вместе с исходниками
в `assets/alpha/0.4.12-niceproxy.3/`; CSS приложения отсутствует.
[AppShell](../ui-unspec/AppShell.md) и [Page](../ui-unspec/Page.md) проверены
в приложении и отмечены как доступные в этом локальном выпуске.

## Поведение полей и обновления

Поле пути пустое по умолчанию, его подсказка — `/`. Пустое значение при сохранении
превращается в корень `/`. Strip-prefix доступен только для валидного явно заданного
некорневого пути; очистка, корень или некорректный путь сбрасывают переключатель.
Все Select используют `popup="overlay"` — библиотечный список вместо системного.
Фоновые обновления не запускают индикатор ручного обновления; операции Cloudflare
не вызывают перезагрузку config/health/port-owners. Прокрутка и черновик сохраняются.

## Единое правило TCP/UDP

В меню создания только HTTP/HTTPS и TCP/UDP. Протокол TCP/UDP выбирается одним
библиотечным overlay-пикером внутри общей формы, без перемонтирования полей.
Кнопка «Создать правило» одна. Форма разделена на «Откуда» (входящий порт, IP
интерфейса Niceproxy) и «Куда» (IP/домен сервиса, его порт). Пустой IP входа
превращается в 0.0.0.0; пустой порт назначения — во входящий. При редактировании
сохранённый явный порт назначения остаётся явным и не меняется от изменения
входящего порта. Превью показывает фактическую схему. Ошибки портов и адресов
расположены у своих полей, IPv6 передаётся без URL-схемы и квадратных скобок.

В форме TCP/UDP адрес и порт располагаются рядом в двух строках через
`Stack direction="row" columns="wide-start"` из локального выпуска .4.
Доли 2:1 сохраняются на 320px. Заголовки «Откуда/Куда» и длинные hint убраны;
доступные имена полей, ошибки и одобренная схема проброса сохранены.
